## 共用功能 fixture

每个用例从同一个**新建集合**开始（建议标识 `V-FUNC-2026-11-03`），按真实界面创建下列笔记。
内部 ID 由创建时生成，必须在执行记录中抄录；下文的 `C1` 表示该集合 ID。

| 代号 | 名称 | 正文（保存前） | 标签 | 用途 |
|---|---|---|---|---|
| F1 | `笔记` | `Alpha 正文` | `课程`、`AI` | 名称／标签／查询 |
| F2 | `Note` | `beta` | `ai`、`复习` | 大小写与标签区分 |
| F3 | `实验记录` | `gamma` | 无 | 草稿与改名 |
| R1 | `引用源` | `参见 ` + 对 R2 的引用 | `课程` | 出站引用 |
| R2 | `目标笔记` | `target` | `复习` | 入站引用 |
| R3 | `第三篇` | `third` | 无 | 增加／删除引用 |
| D1 | `待删笔记` | `delete me` | `课程`、`实验` | 删除清理 |
| D2 | `入站来源` | `参见 ` + 对 D1 的引用 | 无 | 入站引用保留 |
| D3 | `同名笔记` | `old identity` | 无 | 同名重建 |

引用一律通过界面的“插入引用”操作创建，不允许手工拼写 `[[note:...]]` 作为通过证据；手工拼写只用于
V05-04、V05-05 这类**负向**用例。创建完 fixture 后关闭并重开集合，确认 9 篇笔记和 2 条引用已保存。

记录中需要抄录：`C1`、F1—D3 的 note ID、R1/D2 正文中完整引用标记、创建和重开时间。

## 记录要求

- 每个用例必须记录：记录编号、执行人、复核人、开始／结束时间与时区、应用版本和提交、
  Windows 版本、Python／Qt 版本、设备、集合路径类型、`C1` 和 fixture note ID、操作序列、
  预期、实际、界面提示／错误码、证据路径、结论和清理。
- 结论只能是 `未执行`、`阻断`、`失败`、`通过`；没有真实证据时不得写 `通过`。
- 失败时保留现场；不要为了继续后续用例而覆盖数据库。需要重置时复制 fixture 快照并在记录中注明。
- V06-03 的组件级故障注入与界面用例分开记录，不能把自动测试结果填成人工界面通过。
