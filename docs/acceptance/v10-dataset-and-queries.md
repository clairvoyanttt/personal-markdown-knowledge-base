状态：**未执行**。本文件定义正式 V10 性能验收的固定输入、预期结果和运行条件；文中的计数与摘要
是数据集规格的一部分，不是某次运行的实测值。

## 1. 数据集标识与确认值

| 项目 | 值 |
|---|---|
| 数据集标识 | `PMKB-V10-2026-11-03` |
| 规格版本 | 1 |
| 笔记数 | 1000（索引 0—999） |
| 每篇正文 UTF-8 字节数 | 恰好 10240（含空格填充和引用标记） |
| note ID 规则 | 索引 `i` 的 32 位小写十六进制，如索引 42 → `0000000000000000000000000000002a` |
| 名称规则 | `笔记 ` + 四位补零索引，如 `笔记 0042` |
| 标签 | 见第 3 节 |
| 引用 | 前 50 篇各 1 条，指向索引 `i+1`；共 50 条 |
| 修订 | 前 50 篇保存两次，最终修订 2；其余修订 1 |
| 规格内容摘要 | `05632f8c3e132fee88021cdb0123984867c27d0b6cf8f0b7c8f8c2a86fe7667c` |

“规格内容摘要”是对 1000 条固定的 `{index, note_id, name, tags, body, revision,
reference_target_index}` JSON 行（UTF-8、排序键、紧凑分隔符、末尾换行）计算的 SHA-256；计算时
引用集合 ID 固定为 `a`×32，因此与实际创建集合的随机 ID 无关。实际数据库的 SHA-256 和集合 ID
由生成脚本写入清单，必须随记录保存。

## 2. 生成规则

对每个索引 `i = 0..999`：

1. `note_id = f"{i:032x}"`；`name = f"笔记 {i:04d}"`。
2. 正文前缀：`f"笔记 {i:04d} 的正文。\nTOKEN-{i:04d} UniqueMarker。\n"`。
3. 填充句：`课程笔记内容与复习要点，包含中文与 English mixed text 以及数字 2026。\n`。
4. 非引用笔记（`i >= 50`）填充到 10240 UTF-8 字节，不足部分用 ASCII 空格补齐。
5. 引用笔记（`i < 50`）只为正文预留 `10240 - 75` 字节，先填满并用 ASCII 空格补齐，再追加
   `"\n"` 和 `format_reference_marker(C1, note_id(i+1))`；两者合计 75 字节，最终仍恰好 10240。
6. 引用标记形式为 `[[note:<32位集合ID>:<32位目标note ID>]]`，长度 74 个 UTF-8 字节／UTF-16 单元；
   `C1` 是本次创建的集合 ID。目标为索引 `i+1`（1—50），均存在。
7. 标签按第 3 节生成；前 50 篇第一次保存 `base_revision=None`，第二次以同一 `note_id`、
   `base_revision=1` 再保存一次。

正文中的前缀、填充句和标记都是普通正文；查询不依赖 Markdown 结构。前 50 篇的正文在标记前可能有
尾部空格，这是为了精确控制字节数，不得在验收前手工清理。

## 3. 标签分布

先判断覆盖规则，再按 `i % 10` 生成：

| 条件 | 标签 |
|---|---|
| `i % 100 == 10` | `课程`、`复习` |
| `i % 100 == 12` | `AI`、`ai` |
| 否则 `i % 10 == 0` | `课程` |
| 否则 `i % 10 == 1` | `复习` |
| 否则 `i % 10 == 2` | `AI` |
| 否则 `i % 10 == 3` | `ai` |
| 否则 `i % 10 == 4` | `实验` |
| 否则 `i % 10 == 5` | `阅读` |
| 其他 | 无标签 |

分布：`课程` 100、`复习` 110、`AI` 100、`ai` 110、`实验` 100、`阅读` 100；有标签笔记 600，
无标签笔记 400。`AI` 与 `ai` 是两个不同标签，不能合并计数。

## 4. 查询语义

30 条查询使用产品当前的已保存内容查询规则，不另做归一化：

- 关键词必须在名称或正文中作为连续字面串出现；空格有意义，不做分词、全角／半角转换或 Unicode
  归一化。
- 英文大小写不敏感只折叠 ASCII `A`—`Z`；中文和全角字符不变。
- 标签是 AND：结果必须同时具备列出的每个标签；标签比较大小写敏感，`AI` 与 `ai` 不同。
- 查询只看已保存版本；未保存草稿不进入结果。
- 空串和全空白关键词是拒绝，不是“返回全部”；V10 的 30 条查询都是有效关键词。
- 结果摘要定义为：把匹配 note ID 升序排列，按 `\n` 连接（末尾不加换行），对 UTF-8 字节计算
  SHA-256。零结果为 64 个十六进制 `e3b0c442...b855`（空串的 SHA-256）。

## 6. 正式运行条件与顺序

### 6.1 执行前

- 指定真实执行人和复核人；AI 只能准备材料或运行工具自检，不能作为人工执行人。
- 记录设备：Windows 版本和内部版本、CPU 型号／核数、内存、存储介质（SSD／HDD）、集合目录所在
  卷、目录权限（普通用户可读写）、电源模式（接通电源、非省电）、屏幕缩放、是否虚拟机。
- 记录应用版本／提交／分支、Python 版本、Qt 版本、SQLite 版本（如可获取）。
- 记录数据集清单：集合 ID、数据库路径、数据库 SHA-256、笔记数 1000、正文最小／最大字节数、
  引用数 50、规格内容摘要。
- 确认没有另一个进程在写该集合；关闭不必要的应用；记录仍运行的杀毒、同步、索引或远程桌面进程。

### 6.2 预热

1. 启动应用并打开数据集集合，等待首屏加载完成。
2. 依次执行以下 5 条预热查询，每条重复 3 次，丢弃结果和耗时：
   `TOKEN-0001`、`TOKEN-0998`、`笔记 0001`、`笔记 0998`、`TOKEN-0777`。
3. 预热结束后等待 5 秒；不要关闭应用，不要切换集合，不要执行其他写操作。

### 6.3 负载与顺序

- 负载：除应用、记录工具和操作系统自身进程外，不主动制造额外负载；不得同时复制数据集、扫描磁盘、
  播放视频或运行构建。若存在不可控后台负载，记录名称和时间段。
- 顺序：单次运行，严格 Q01→Q30；每条之间间隔 1 秒；不得为了得到更好数字重跑某条后只保留低值。
- 计时：从用户触发搜索（回车或点击搜索）开始，到结果列表和总数完成渲染为止；使用屏幕录制逐帧、
  应用埋点或经复核的外部计时，方法全程一致并在记录中注明。
- 失败处理：某条查询报错或结果错误时继续执行后续查询，但整轮标记失败；保留错误文本、时间和截图。
- 结束后关闭应用，记录结束时间；如需重测，使用新的记录编号并说明原因。

## 7. 判定

- 正确性：Q01—Q30 每条的条数和结果摘要都与第 5 节一致；任何一条不一致，V10 失败。
- 性能：至少 29 条耗时 ≤ 2000 ms（含 2000 ms）；同时记录全部 30 条的耗时、最小值、中位数、
  P95 和最大值。只有 28 条或更少满足阈值即失败。
- 环境：必须来自真实执行设备和真实界面；工具直接调用存储服务的数字只能作为组件级参考，不能填入
  正式 V10 结论。
- 结论只能是 `未执行`、`阻断`、`失败`、`通过`。没有执行人、设备、数据集清单、逐条记录和证据时，
  保持 `未执行`。

## 8. 开发自检工具（非验收）

- `scripts/prepare_v10_acceptance_data.py`：在空目录生成上述数据集和清单；只用于准备固定输入。
- `scripts/run_v10_acceptance.py`：按固定顺序调用存储查询 30 次，输出逐条耗时和摘要；它是
  **组件级工具自检**，测量的是服务调用而不是界面渲染，输出带 `UNSIGNED_TOOL_RUN`，不得当作
  正式 V10 通过。
- 两个脚本都不进入用户安装包；`scripts/benchmark_c.py` 同样只作参考，不是正式验收执行器。
