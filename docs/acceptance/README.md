# A 侧验收材料（V01／V04／V05／V06／V10）

本目录是 A 侧为完整产品验收准备的可复用输入，不是验收结果。目录内所有 V 用例当前状态均为
**未执行**；没有真实执行人、设备、屏幕或日志证据时，不得写成“通过”。

## 范围与边界

- 覆盖：V01 名称／标签、V04 查询、V05 引用、V06 删除、V10 性能。
- 不覆盖：V02／V03／V07—V09／V11—V16，以及 B 的导出、D 的恢复、离线、隐私和真实数据验收。
- `scripts/prepare_v10_acceptance_data.py`、`scripts/run_v10_acceptance.py` 是开发自检工具，
  不是用户安装包内容，也不是正式验收执行器。工具输出只能作为组件级证据，不能替代真实 Qt
  界面、指定执行人和设备记录。
- 正式验收记录按 `docs/development/d-validation-matrix.md` 的字段填写；本目录只提供固定输入、
  预期结果和记录模板。自动测试或工具自检通过，不会自动把产品状态改为“通过”。

## 固定数据集

V10 数据集标识：`PMKB-V10-2026-11-03`（规格版本 1）。

- 1000 篇笔记，索引 `i = 0..999`，`note_id` 为 `i` 的 32 位小写十六进制；
- 名称固定为 `笔记 ` + 四位序号（如 `笔记 0042`）；
- 每篇正文的 UTF-8 字节数**恰好 10240**；
- 前 50 篇各有一条指向下一篇的引用，并各保存两次（第二次 `base_revision=1`）；
- 标签按固定周期生成，`AI` 与 `ai` 是两个不同标签；
- 30 条固定查询的预期计数和结果摘要见 `v10-queries.json`。

数据集由 `scripts/prepare_v10_acceptance_data.py` 在空目录中生成。生成清单必须随验收记录保存；
清单中的集合 ID 会因每次创建而不同，但 30 条查询的预期计数和摘要不受影响。

## 执行与责任

- A 负责组织、提供输入和检查记录完整性；C 负责存储／查询实现的技术澄清。
- 正式执行人必须是实际参与者；记录中只写真实姓名或明确的项目角色，不写“AI 已通过”。
- AI 可以准备材料、运行工具自检、整理草稿，但不得被列为人工执行人或审批人。
- 同一用例至少由一名未参与实现的人复核记录与证据；无法满足时保留“未执行”或“待复核”，
  不得补造签名。
- 设备、系统、Python／Qt 版本、时间、时区、数据集清单、逐条耗时和原始输出必须来自实际运行。

## 证据与隐私

- 公开仓库只放固定输入、预期和空白模板；真实笔记内容、用户目录、日志、截图、数据库文件、
  安装包和个人设备信息不得上传。
- 证据保存在仓库外的受控目录，记录中填写证据路径或证据编号，不粘贴敏感内容。
- 性能数字必须注明是“工具自检”还是“真实界面正式验收”；两者不能互相替代。
