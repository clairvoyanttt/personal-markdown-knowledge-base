## 一、背景与问题陈述

学生与知识工作者需要持续记录、整理、查找和关联知识。随着笔记积累，用户可能面临内容难以定位、知识关系难以追踪，以及未保存修改被误丢弃等问题。这些问题根据题目和使用场景推导，未开展用户访谈验证。

本工具围绕“记录—组织—查找—关联—输出”流程，支持用户在 Windows 11 上管理个人本地 Markdown 笔记，并通过手动保存、备份和恢复保护数据。

首版目标：

- 编辑和预览 Markdown，识别未保存、已保存和保存失败状态。
- 使用标签和全文检索定位已保存笔记。
- 建立双向引用，改名后保持关联，删除后识别失效引用。
- 导出单篇 Markdown，明确内部引用和附件的限制。
- 手动备份已保存数据，恢复为独立集合，不覆盖当前集合。

## 三、统一业务规则、优先级与编号

### 3.1 数据版本与手动保存

“当前编辑版本”是当前编辑界面的内容，可能尚未保存；“已保存版本”是最近一次成功保存的数据。

| 操作或界面 | 使用的数据版本 |
|---|---|
| 当前笔记编辑界面，包括待保存名称、标签和内部引用 | 当前编辑版本 |
| Markdown 预览 | 当前编辑版本，无需先保存 |
| 笔记列表名称、标签筛选、全文搜索及引用目标名称 | 已保存版本 |
| 其他笔记的反向引用列表 | 已保存版本 |
| 单篇 Markdown 导出 | 已保存版本 |
| 手动备份 | 已保存版本 |

正文、名称、标签及内部引用的修改均需要手动保存。改名输入可在当前编辑界面显示；保存前，笔记列表、标题检索和引用目标名称仍依据已保存名称。保存时按 FR01 去除首尾空白、校验名称并排除自身判重；保存成功后更新名称，已有引用仍指向原笔记。校验或保存失败时保留待保存输入，已保存名称及引用关系不变。

统一处理规则：

1. 修改后，当前编辑界面显示修改，并标识未保存。
2. 保存前，标签筛选、全文搜索和反向引用仍依据已保存版本。
3. 保存成功后，上述结果更新。
4. 保存失败时，保留当前编辑内容，上述结果继续依据原已保存版本。
5. 普通关闭未保存笔记时，按 FR10 提醒；明确确认删除的流程按 FR01 处理。
6. 预览、检索、导出和备份不得隐式保存编辑中的修改。

预览用于检查当前编辑效果；检索和反向引用用于查找已保存知识。两者使用不同版本是明确的业务规则。

### 3.2 名称与标签

- 新建或改名时，笔记名称去掉首尾空白后保存；处理后为空则拒绝。
- 同一集合内不允许不同笔记重名。去掉首尾空白后判重，英文名称不区分大小写；改名判重排除当前笔记自身。
- 重名操作失败时，已有笔记及引用关系保持不变。
- 标签去掉首尾空白、拒绝空标签，同一笔记不重复添加同名标签。
- 英文标签区分大小写，不套用笔记名称的大小写判重规则。

**D1 集合定义与生命周期（U14 第1项采纳）**

“笔记集合”指存放于一个用户选择的本地位置、包含笔记名称、正文、标签及集合内引用关系的一组数据。集合在界面以其完整本地位置识别，并另有不随名称或位置变化的集合标识用于校验引用归属，见 D3；不增加集合独立改名或删除功能。名称判重、标签筛选、搜索及引用解析仅在当前集合内执行。

一次只打开一个活动集合；新建集合选择空本地目录，成功后成为活动集合；打开集合选择已有有效集合的位置。切换集合通过打开另一集合完成。离开当前集合前，对全部未保存笔记执行 FR10；取消或保存失败时停止切换，保留当前集合和编辑内容。检查目标无效、不可读等失败时也不得关闭原集合或丢弃编辑内容；目标检查在执行“放弃修改”前完成，只有实际切换成功才丢弃明确选择放弃的修改。用户已经成功执行的手动保存不回滚。

备份只对应触发操作时的一个活动集合；备份保存该集合的来源位置、备份时间和已保存笔记数量，作为识别信息，不作为恢复目的地。恢复仍要求选择空位置，形成新独立集合。成功时显示恢复位置和数量，提供“打开恢复集合”，也可稍后通过“打开集合”选择该位置；仅恢复成功不自动切换。打开恢复集合仍遵守 FR10。恢复后引用仅在恢复集合内解析，不能跳回原集合。

**理由：** 给现有集合内判重、备份及独立恢复提供明确操作入口和作用域，避免误恢复至原位置；无需集合删除、合并或跨集合关系。

<a id="D2"></a>

**D2 名称、标签及导出命名（U14 第2项采纳）**

- 名称去首尾空白后为 1—100 个 Unicode 码点；标签去首尾空白后为 1—30 个 Unicode 码点。码点是 Unicode 字符计数单位，中文通常计 1，表情按实际码点计数；不按 UTF-8 字节计数，不承诺复杂表情一律计 1。
- 名称与标签均为单行文本；先拒绝输入中的 U+0000—U+001F 或 U+007F 控制字符（包括制表符、换行），再裁剪其余允许的首尾空白并校验长度及空值；名称判重及标签大小写规则仍按 3.2，不新增字符正规化规则。
- 每篇笔记最多 20 个不同标签，按大小写区分后的标签项计数；重复添加原有标签不占新名额。超限操作说明上限，保留原数据、编辑输入和未保存状态，不截断或悄悄丢弃内容。
- 不增加集合总笔记数或全局标签数硬上限。NFR03 的 1,000 篇及每篇 10 KB 是性能测试规模，不是禁止保存第 1,001 篇或更长正文的产品规则；范围外数据不自动享有相同响应时间保证。
- 默认导出文件名为 `note-<处理后的已保存名称>.md`。仅在生成文件名时，将 Windows 文件名禁用字符 `< > : " / \ | ? *` 替换为下划线，移除末尾点和空格；处理后为空则使用 `note.md`。固定 `note-` 前缀避免名称为 `CON` 等保留设备名时直接成为该文件名。笔记本身的名称不因此改写。
- 默认名示例：已保存名称“课程/笔记” → `note-课程_笔记.md`；“CON” → `note-CON.md`；“复习.md” → `note-复习.md.md`，固定追加一次导出扩展名，不猜测标题后缀。用户可另选合法文件名，最终须以 `.md` 结尾（大小写均可）；缺少扩展名时追加 `.md`。不合法或路径不可写时提示并允许重选，不截断名称；目标已存在仍按 FR09 拒绝覆盖。

**外部依据：** 文件名禁用字符、保留设备名和末尾点/空格约束参考[Microsoft 文件命名说明](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)。该资料只支持操作系统约束。100/30/20、note-前缀及替换策略先由 AI 提出，再由 U14 第2项采纳，并非老师原题。

**理由：** 100/30/20 是 AI 面向课程首版提出、由 U14 采纳的可测试边界，并非访谈结论或平台强制值；限制单条输入及标签操作规模。文件名处理将笔记业务名称与操作系统约束分开，保留已确认的拒绝覆盖规则。

<a id="D3"></a>

**D3 内部引用书写、归属校验及恢复（U14 第3项采纳并补充）**

**标识与格式的具体落实：** 为满足“复制到其他集合不能静默指向另一篇”这一结果，本轮 AI 将此前仅含局部标识的建议改为携带集合归属与目标身份的完整标记。这是需求层面的可见表示及校验结果，不限定数据库、文件布局或标识生成算法。

- 使用“插入内部引用”，从当前集合的已保存笔记中选择目标，应用生成 `[[note:<集合标识>:<笔记标识>]]`。两种标识各用 32 个小写十六进制字符表示 128 位标识，不从名称、位置、编号或计数器推导；新集合标识使用至少128位随机性或等效的全局唯一生成方式独立产生；检测到已知冲突时重新分配或拒绝，不带冲突继续使用，不依赖跨设备在线注册。应用不得在已知不同集合间复用集合标识。笔记标识在集合内唯一，改名不变，删除后不复用；集合标识在集合自身生命周期内不变。新建或打开时发现同一标识被两个已知独立集合复用且无法证明其归属时，拒绝把它们作为可相互匹配的有效引用环境并显示身份冲突；不按位置猜测。具体生成算法不指定。
- 文档格式示例（不是已运行系统生成的真实数据）：

    `[[note:6a7e325c90db4f11a38b742dd589c201:b90a6c157e884fea912307dcd2a14560]]`

  前段表示所属集合，后段表示目标笔记。`K1` 只属于上一轮解释用短示例，不是本轮有效标识或允许的正式标记。用户无需手工填写长标识，选择笔记后由应用生成。
- 源文本保留完整标记；编辑界面在标记旁提示目标已保存名称，预览用该名称呈现。目标改名成功后名称提示更新，标记不变，不改写或隐式保存来源笔记。目标名称修改未保存时仍显示旧保存名称。
- 识别标记时先检查完整语法及集合归属，再按笔记标识确定目标；仅在集合标识与当前集合一致且目标是有效笔记时建立有效关系。不按名称、相似文本或局部标识回退匹配，不静默改写错误归属。当前集合没有对应目标时也不能自动新建或换绑。
- 从集合 A 复制完整标记到另一集合 B，标记保留原文；即使 B 有同名笔记或相同笔记标识，也显示“失效引用：<可用原目标名称或未知目标>（引用来自其他集合，无法跳转）”。不能打开 B 中任何替代笔记，也不支持打开 A。用户可删除该标记，再用插入命令选择 B 的目标；这些编辑须手动保存，首版不提供自动跨集合修复。
- 当前集合中目标已删除时，编辑界面和预览显示“失效引用：<原目标名称>（目标已删除，无法跳转）”；标识不存在、无法证明目标曾存在时显示“失效引用：未知目标（目标标识不存在或不可用，无法跳转）”。均有文字标识，不能只靠颜色。激活已保存失效引用时显示对应原因，不打开其他笔记。同名重建不会恢复旧引用。
- 围栏及行内代码中的标记按代码原文呈现，不建关系；不符合完整语法的标记（含旧短示例）按普通文字保留，不产生反向引用。符合完整语法但集合归属或目标无效的标记才按前述失效规则提示。不存在的标识不得仅因某篇笔记名称相同而被接受。
- 插入、复制标记或删除标记均属于当前笔记修改。编辑界面和预览可立即显示；有效的已保存关系、检索及其他笔记反向引用只在保存成功后更新，保存失败不改变已保存版本。本轮仍不新增未保存引用激活是否跳转的验收要求。
- 备份包含来源集合标识、笔记标识、已保存正文/标签/引用及必要的失效状态和历史名称识别信息。恢复成功产生新的独立集合标识，保留对应笔记标识；将备份中属于来源集合的有效引用标记内的集合标识一致转换为恢复集合标识，使其指向对应恢复笔记。只在恢复产物中转换，原集合及备份文件不改变。
- 恢复中的已删除/不存在目标继续失效，不分配同标识给新笔记；保留已有历史名称和失效原因。来源集合内这类标记的集合归属随恢复转换，但不得因此找到替代笔记。原本来自第三集合的失效标记不转换归属，仍失效；代码中的示例标记不转换。备份内部的标识或关系冲突、有效关系无法对应恢复目标时拒绝恢复并说明原因，不按名称猜测修复。每次恢复均产生新的集合标识；两个恢复集合相互独立。恢复得到的是完整已保存集合，转换不是用户编辑的隐式保存，也不触发原集合编辑内容的自动提交。
- 单纯复制原集合正文到恢复集合仍是普通跨集合复制，不能获得恢复流程的标识转换；原标记显示跨集合失效。恢复流程的受控转换是重建独立集合的必要步骤，不是跨集合引用能力，也不是自动保存用户当前编辑内容。
- 导出仍只使用已保存正文及关系：有效标记输出 FR09 的不可点击普通文本；目标删除、标识不存在或跨集合失效分别附可读原因，不保留完整标记作为链接。代码内标记保持代码原文，外部 Markdown 网页链接不变；目标名称中的 Markdown 特殊字符按普通文本处理，不能形成有效内部链接。

**用户可见结果：** 正常插入后看到目标名称；合法改名后仍打开同一目标；复制到其他集合、目标不存在或被删除时看到明确失效原因；通过备份恢复并打开新集合后，已有效引用打开对应恢复笔记，原集合不受影响。

**理由：** 仅限定“在当前集合解析”不能防止局部 `K1` 在另一个集合恰好对应其他笔记。完整归属标识与不可复用的目标身份共同校验，消除这一回退路径；恢复显式转换归属，兼顾新独立集合与已有关系连续性。长度及具体可见格式由本轮 AI 落实 U14 的安全要求，非老师原文；U15已明确完成本轮文本核查，不涉及软件运行验收。

## 四、功能需求与验收标准

### FR01 笔记管理与名称唯一性

**优先级：高（H）**

**来源：** 题目仅给出笔记工具类别 [T01](#T01)；管理动作及验收组织来自 AI [R01／FR01](#R01-source) 方案，后经 [U12](#U12) 整体认可；删除确认与不重名见 [U03 第5项](#U03)，裁剪/英文判重见 [U04 第一条](#U04)，排除自身与中文空格示例见 [U05](#U05)，改名保存/删除保护见 [U10 第2项](#U10)。本轮长度与控制字符限制属 AI [D2](#D2)，由 [U14](#U14) 采纳；本轮文本经 [U15](#U15) 核对认可。

用户能够新建、打开、改名和删除笔记。新建或改名时，名称去掉首尾空白后保存；处理后为空则拒绝。同一集合内不允许不同笔记重名，英文名称判重不区分大小写。改名判重时排除当前笔记自身。

验收方法：

1. 新建并保存笔记后，可从列表打开。
2. 在不存在名称冲突时，输入名称 `  Note  `，成功保存后的名称为 `Note`。
3. 输入空名称或全空白名称，拒绝新建或改名，显示原因。
4. 已有笔记 A，名称为 `Note`：
   - 新建另一篇笔记，输入 `note`、`NOTE` 或 ` Note `，均提示重名并拒绝。
   - 将另一篇笔记 B 改名为 `note`、`NOTE` 或 ` Note `，均提示重名并拒绝。
   - 对 A 自身执行上述名称操作，不得仅因与 A 的原名称匹配而提示与另一篇笔记重名。
5. 已有笔记 A，名称为 `笔记`：
   - 将另一篇笔记 B 改名为 ` 笔记 `，去掉首尾空白后判为重名，提示并拒绝。
   - 新建另一篇名称为 `笔记` 或 ` 笔记 ` 的笔记，同样提示重名并拒绝。
6. 重名失败后，不产生第二篇同名笔记；已有笔记的名称、正文、标签及引用关系不变。
7. 合法改名保存成功后，列表显示去除首尾空白后的新名称，引用行为满足 FR08。
8. 删除前显示确认提示；若存在未保存修改，同时说明“该笔记及未保存修改将被删除，首版无回收站”。取消后保留笔记、当前编辑内容及未保存状态；确认后从正常列表移除，相关引用按 FR08 处理。模拟删除失败时，已保存数据、当前编辑内容及引用关系保持不变。
9. 合法改名用例：集合已有 A（已保存名称“课程笔记”）和 C（已保存名称“复习提纲”），名称“线性代数整理”尚不存在；样例正文不含这些名称。将 A 编辑为“线性代数整理”但不保存，编辑界面可见待保存名称，列表及引用目标名称仍为“课程笔记”；标题查询“课程笔记”仍命中 A，“线性代数整理”不命中 A。保存成功后，名称和查询结果更新为“线性代数整理”，已有引用继续指向 A。
10. 重名改名用例：独立重置上述集合，尝试将 A 改为“ 复习提纲 ”。去首尾空白后与另一篇 C 重名，拒绝保存，A、C 的已保存名称及引用关系不变，待保存输入保留。
11. 保存失败用例：独立重置上述集合，输入合法且未被占用的新名称“线性代数整理”，模拟保存失败。编辑输入及未保存状态保留，列表、标题检索、引用目标名称继续使用“课程笔记”。放弃修改并关闭不提交改名。

**补充验收（D2，U14采纳；验收未执行）：** 去空白后的名称为 100 个码点时允许继续保存流程，101 个时拒绝并说明上限；分别验证新建及另一篇改名，原已保存数据和引用不变。另用中间、首尾含换行/制表符等控制字符的名称验证拒绝，不能先裁剪掉控制字符再接受；包含文件名禁用符号但符合此名称规则的“课程/笔记”仍可作为笔记名称，不将导出文件名规则套用到笔记名称。所有例子分别在无冲突集合测试，超长或非法输入不自动截断，失败仍按 FR10 保留待保存输入。

### FR03 Markdown 预览

验收方法：

**补充验收（D3，U14采纳；验收未执行）：** 未保存插入有效引用标记后，预览显示目标的已保存名称，其他笔记反向引用不更新；围栏及行内代码中的相同标记保留原文，不生成引用。检查源文本未被预览改写。不验收未保存引用的跳转行为。

### FR04 标签编辑与筛选

**优先级：高（H）**

**来源：** 标签为 [T01](#T01) 题目要求；裁剪、空标签、重复及大小写见 [U03 第4项](#U03)，保存/筛选版本见 [U04 第二条](#U04)。长度、20项及控制字符限制属 AI [D2](#D2)，由 [U14](#U14) 采纳；本轮文本经 [U15](#U15) 核对认可。

用户能够添加、移除标签，并按已保存标签筛选笔记。标签修改需要手动保存。

验收方法：

1. 输入 `  AI  `，当前编辑界面显示标签 `AI`。
2. 空标签及全空白标签被拒绝。
3. 同一笔记重复添加 `AI` 不产生重复项；`AI` 和 `ai` 可以作为不同标签存在。
4. 在 A 中添加标签但不保存，编辑界面可见该标签，筛选时 A 不因本次修改进入结果；保存成功后进入结果。
5. 从 A 移除该标签但不保存，编辑界面显示移除结果，筛选仍包含 A；保存成功后才移除 A。
6. 标签保存失败时，保留编辑中的修改，筛选仍依据原已保存版本。
7. 仅修改标签后关闭，也触发 FR10 的未保存提醒。

**补充验收（D2，U14采纳；验收未执行）：** 30 个码点标签可添加，31 个被拒绝；20 个不同标签可存在，添加第 21 个新标签被拒绝。满 20 项时重复添加已有标签仍不产生新项；`AI` 与 `ai` 各占 1 项。输入含控制字符的标签被拒绝，包括首尾制表符或换行，不能先裁剪掉控制字符再接受。移除一个标签后可再添加新标签，但保存前筛选仍使用旧版。超限失败不截断输入、不更新已保存筛选，关闭按 FR10。

### FR05 全文检索

**优先级：高（H）**

**来源：** 全文检索为 [T01](#T01) 题目要求；字面匹配、大小写及未保存排除见 [U03 第4项](#U03)；空白查询与改名检索澄清见 [U10 第2项](#U10)。标题/正文范围及细则为 AI 方案，经 [U12](#U12) 整体认可；当前集合边界属 [D1](#D1)，由 [U14 第1项](#U14) 采纳。

用户能够对已保存笔记的标题和正文进行连续字面匹配检索，英文不区分大小写。

验收方法：

1. 标题及正文中的唯一关键词均能检索到对应笔记；点击结果打开对应笔记。
2. `Markdown` 可被 `markdown` 命中。
3. 正文包含“知识管理”时可命中该查询；仅包含“知识与管理”时不能据此命中。
4. 查询为空，或仅包含空白字符（如空格、制表符）时，提示输入关键词，不执行检索，并清除旧查询结果。分别用空字符串、三个空格和一个制表符验证。其他查询仍按既定连续字面匹配规则处理，不额外裁剪非全空白查询。
5. 无匹配时明确显示无结果，不残留上次结果。
6. 新增关键词但未保存时不能据此命中，保存后可以命中。
7. 删除已有关键词但未保存时，仍能按原已保存内容命中；保存后不再据此命中。
8. 保存失败时，结果继续依据原已保存版本。

标签不属于全文检索字段，按 FR04 单独筛选。

**补充验收（D1，U14采纳；验收未执行）：** 两个集合各自有同名或同关键词笔记；打开任一集合时搜索只返回该集合的已保存内容，切换后不残留另一集合结果。跨集合重名不是 FR01 的冲突。

### FR06 内部引用编辑与跳转

**优先级：高（H）**

**来源：** 双链引用为 [T01](#T01) 题目要求；禁止同名候选见 [U03 第5项](#U03)，引用手动保存见 [U04 第二条](#U04)，名称冲突联动见 [U05](#U05)。插入命令、带标识标记及名称呈现原则属 AI [D3](#D3)，由 [U14 第3项](#U14) 原则采纳；本轮文本经 [U15](#U15) 核对认可；本轮复合集合/笔记标识与恢复转换为 AI 落实 [U14 第3项](#U14) 的安全要求，具体文本经 [U15](#U15) 核对认可。

用户能够建立或移除指向同一集合内其他笔记的内部引用。引用编辑需要手动保存。

验收方法：

1. 在 A 中添加指向 B 的引用，当前编辑界面立即可见；保存后激活引用可打开 B。
2. 添加引用但未保存时，B 的反向引用不因本次修改出现 A；保存后出现 A。
3. 移除引用但未保存时，编辑界面显示移除结果，B 的反向引用仍包含 A；保存后才移除 A。
4. 按 FR01 验证名称规则，目标列表不存在同一集合内的重名候选项。
5. 新建另一篇笔记或将另一篇笔记改为与 B 冲突的名称，操作失败后，A 中已有引用仍指向原 B。冲突按 FR01 的去首尾空白及英文不区分大小写规则判断。
6. 仅增删内部引用后关闭，也触发 FR10 的未保存提醒。

用户可见标记及校验规则按 D3；不规定实现这些规则的数据库或存储技术。

**补充验收（D3，U14采纳；验收未执行）：**

7. 从当前集合已保存目标列表选择 B，生成符合 `[[note:<集合标识>:<笔记标识>]]` 的源文本标记，编辑界面和预览显示 B 的已保存名称；手动保存后可打开 B，并产生 FR07 反向引用。
8. 在同一集合中复制该完整标记到 C 并保存，仍指向 B；仅删除 A 中标记但未保存时，B 的反向引用仍含 A，保存后移除 A、保留 C。
9. 将 B 合法改名并保存，A 的标记原文不变、显示名称更新且仍打开原 B，不改写或隐式保存 A。未保存的目标改名不改变 A 显示名称。
10. 不符合完整语法的 `[[note:]]` 或旧短示例 `[[note:K1]]` 保留为普通文本，不产生关系；代码中的标记同样不产生关系。符合语法但无目标的标记按 FR08 失效提示处理。
11. 只列出当前集合目标；跨集合复制完整标记时检查归属，不能仅用局部笔记标识匹配。

12. 集合 X 有 A→B 的已保存有效引用，集合 Y 有同名笔记 B'；准备 Y 中局部笔记标识与 X 的 B 相同、集合标识不同的受控样例。复制 A 的完整标记到 Y 的 C 并保存，编辑界面和预览显示“引用来自其他集合，无法跳转”；激活时不打开 B'，B' 的反向引用不含 C，标记原文不被自动改成 Y 的归属。
13. 在 X 中准备符合完整语法但目标笔记标识不存在的标记并保存；即使有同名候选也显示不存在/不可用，不能静默关联，反向引用不新增来源。
14. 删除 B 后保留原标记，再新建同名 B''；旧标记继续失效，不能打开 B''、不在 B'' 建立反向引用。备份恢复后的对应检查见 FR11 第15—17项。

这些条件规定用户可见格式、身份及归属校验行为，不规定数据库/文件实现，不增加未保存引用跳转验收。

### FR07 反向引用

**优先级：高（H）**

**来源：** 反向关系为 AI [R01／FR07](#R01-source) 对 [T01](#T01) 双链引用的展开；已保存关系规则在 [U04 第二条](#U04) 明确，并由 [U10 第3项](#U10) 要求保留；[U12](#U12) 认可已有验收细则；本轮复合集合/笔记标识与恢复转换为 AI 落实 [U14 第3项](#U14) 的安全要求，具体文本经 [U15](#U15) 核对认可。

用户能够查看哪些已保存笔记引用当前笔记，并打开引用来源。

验收方法：

1. A、C 引用 B 并保存后，B 的反向引用包含 A、C。
2. 从列表可以打开对应来源笔记。
3. A 移除引用但未保存时，列表仍包含 A；保存成功后移除 A，保留 C。
4. 新增引用未保存时不更新列表；保存失败时也不更新。
5. 重新打开集合后，反向引用与已保存关系一致。

**补充联动验收（D1/D3，U14采纳；验收未执行）：** 反向引用仅来自当前集合已保存、归属校验通过且目标有效的非代码标记；跨集合复制、目标不存在/删除、格式不合法文字及代码示例不进入列表。标记复制/删除遵守原保存成功才更新规则，不改变 P06。

### FR08 引用目标改名与删除

**优先级：高（H）**

**来源：** 改名保留、删除失效见 [U02 修改第1项](#U02)；名称联动和排除自身见 [U05](#U05)；同名重建不得自动重绑为 AI 细则，经 [U12](#U12) 整体认可。失效提示文案/格式属 AI [D3](#D3)，由 [U14](#U14) 采纳；本轮文本经 [U15](#U15) 核对认可；本轮复合集合/笔记标识与恢复转换为 AI 落实 [U14 第3项](#U14) 的安全要求，具体文本经 [U15](#U15) 核对认可。

合法改名后已有引用继续指向原笔记；目标被删除后，引用显示失效。

验收方法：

1. A 引用 B，选择集合中尚不存在的新名称 B2，将 B 合法改名并保存后，A 的引用仍打开原笔记，B2 的反向引用仍包含 A。保存前引用目标名称仍依据已保存名称 B。
2. 将 B 改为与同一集合内另一篇笔记冲突的名称，或改为去除首尾空白后为空的名称，操作被拒绝，原引用关系不变。冲突按 FR01 判断，并排除 B 自身；合法的自身名称调整按第 1 项验证引用保持关联。
3. 删除 B2 后，A 中相关引用显示失效，激活时提示目标已删除或不可用。
4. 随后新建名为 B2 的另一篇笔记，原失效引用不能自动关联到新笔记。

不限定实现引用身份和关联保持的内部技术。

**补充验收（D3，U14采纳；验收未执行）：** 删除 B 后，在 A 的编辑界面和预览检查带文字的“失效引用：B（目标已删除，无法跳转）”；激活已保存引用显示失败原因，不打开其他笔记。再新建 B，原标记仍失效。无历史名称的不存在目标显示“失效引用：未知目标（目标标识不存在或不可用，无法跳转）”；跨集合标记显示“引用来自其他集合，无法跳转”，均不回退按名称或局部标识关联。提示显示不自动删除标记或保存 A；用户移除标记后仍须手动保存。

### FR09 单篇 Markdown 导出

**优先级：高（H）**

**来源：** 导出为 [T01](#T01) 题目要求；单篇 Markdown 及不承诺附件打包见 [U02 第4项](#U02)；内部引用普通文本、外部链接保留见 [U03 第2项](#U03)；已保存与警告见 [U04 检查第2项](#U04)；拒绝覆盖经 [U10 第2项](#U10) 采纳。具体默认文件名属 AI [D2](#D2)、标记转换属 [D3](#D3)，由 [U14](#U14) 采纳；本轮文本经 [U15](#U15) 核对认可；本轮复合集合/笔记标识与恢复转换为 AI 落实 [U14 第3项](#U14) 的安全要求，具体文本经 [U15](#U15) 核对认可。

用户能够导出单篇笔记的已保存版本。内部引用转换为不可点击的可读普通文本，外部网页链接保留原样，图片和附件不打包。

有效内部引用输出示例：

    内部引用：数据结构复习（仅供识别，导出后不支持应用内跳转）

目标删除时的失效内部引用输出示例：

    失效内部引用：数据结构复习（目标已删除，无法跳转）

跨集合或不存在目标输出为普通文本，分别说明“引用来自其他集合，无法跳转”或“目标标识不存在或不可用，无法跳转”；没有历史名称时写“未知目标”，不把名称猜测成另一篇笔记。

验收方法：

1. 导出前提示：内部引用不保留应用内跳转能力，图片和附件不打包。
2. 当前笔记存在未保存修改时，提示导出不包含这些修改，提供“返回保存／继续导出”。
3. 返回保存时不执行本次导出；继续时仅导出已保存正文和引用状态，不包含编辑中的正文或引用修改。
4. 内部引用输出不生成 Markdown 链接、Wiki 链接、应用链接或 HTML 链接，在 Markdown 阅读器中不表现为有效内部链接。
5. 目标名称包含 Markdown 特殊字符时，也不能使转换结果形成链接。
6. 外部网页链接的 Markdown 源文本保持原样；图片和附件路径保留原文本，不复制资源文件。
7. 成功后显示文件位置；失败时显示原因，不提示成功，源笔记不变。所选导出目标文件已存在时，拒绝覆盖，提示选择其他文件名或位置，或取消；取消及失败均不修改已有文件。
8. 预先放置内容已知的目标文件，尝试导出到相同路径，验证拒绝覆盖提示且已有文件字节保持不变；取消后源笔记不变。另选不存在的路径时，按正常导出流程验收。
9. 文件可用文本编辑器读取，除规定的引用转换外，正文、中文及代码保持一致。

**补充验收（D2/D3，U14采纳；验收未执行）：**

10. 在已保存名称为“课程/笔记”、“CON”、“复习.md”的独立样例上检查默认名依次为 `note-课程_笔记.md`、`note-CON.md`、`note-复习.md.md`；当前未保存改名不影响默认名。用户另选“输出”时补为 `输出.md`，选择 `输出.MD` 时不重复追加。
11. 两个不同名称经文件名替换后若得到相同输出路径，第二次仍拒绝覆盖，不自动覆盖、不改变原笔记；选择非法名称或不可写路径时说明原因，允许重选或取消。
12. 已保存有效引用、跨集合复制、标识不存在及目标删除的标记分别转为前述普通文本，不保留可跳转标记，不静默换成其他笔记名称；代码中的标记保留代码文字，外部链接不改。用包含 Markdown 特殊字符的目标名称确认输出不能形成有效内部链接，未保存引用不混入输出。

默认命名仅处理导出文件名，不更改 FR01 的业务名称及引用目标身份。

### FR10 手动保存与关闭保护

**优先级：高（H）**

**来源：** 手动保存/关闭提醒见 [U02 第5项](#U02)，标签和引用修改见 [U04 第二条](#U04)，改名/删除保护见 [U10 第2项](#U10)；三种关闭选择为 AI 细则，经 [U12](#U12) 整体认可。集合切换衔接属 AI [D1](#D1)，由 [U14](#U14) 采纳；本轮文本经 [U15](#U15) 核对认可。

用户手动保存笔记，识别未保存、已保存和保存失败状态。正文、名称、标签和内部引用修改受同一保存规则约束。普通关闭和退出采用关闭保护；经明确确认的删除操作按 FR01 的删除流程处理，不重复执行普通关闭提示。

验收方法：

1. 分别只修改正文、只编辑名称、只修改标签、只增删引用，均出现未保存状态。
2. 保存成功后显示已保存状态，重新打开可读取保存后的正文、名称、标签和引用。
3. 保存成功后，笔记列表名称、标签筛选、全文检索、引用目标名称及反向引用更新为新版本，引用目标身份保持不变。
4. 模拟保存失败：显示原因，保留当前编辑内容及未保存状态；列表名称、筛选、搜索、引用目标名称和反向引用继续使用原已保存版本。名称校验失败时同样不更新已保存数据。
5. 普通关闭未保存笔记时提供“保存后关闭／放弃修改并关闭／取消”，名称修改也适用：
   - 保存后关闭：仅在保存成功后关闭。
   - 放弃修改并关闭：不提交编辑中的修改，已保存版本保持不变。
   - 取消：留在编辑界面并保留修改。
6. 退出应用时，对所有未保存笔记执行同等保护。
7. 修改后不主动保存，不能因预览、筛选、搜索、导出或备份而被自动保存。
8. 删除含未保存修改的笔记时，按 FR01 显示说明未保存修改会被删除的确认。取消后编辑内容和未保存状态保留；确认后删除并按 FR08 更新失效引用；删除失败时不改变已保存数据及引用关系。

**补充联动验收（D1/D2/D3，U14采纳；验收未执行）：** 集合切换前对全部未保存笔记执行现有三种选择；任一取消、名称/标签校验失败或保存失败时不切换。只插入或移除引用标记也有未保存提醒。超长输入失败不丢弃编辑内容；不因生成引用标记、预览目标名称或生成导出文件名而隐式保存。

### FR11 手动备份与独立恢复

**优先级：高（H）**

**来源：** [T01](#T01) 仅要求分析备份策略，并未强制备份功能；手动备份纳入见 [U02 第2项及修改第2项](#U02)；空位置独立恢复及已保存备份见 [U03 第1项](#U03)，拒绝覆盖经 [U10 第2项](#U10) 采纳；备份来源/打开恢复集合属本轮 AI [D1](#D1)，由 [U14](#U14) 采纳；本轮文本经 [U15](#U15) 核对认可；本轮复合集合/笔记标识与恢复转换为 AI 落实 [U14 第3项](#U14) 的安全要求，具体文本经 [U15](#U15) 核对认可。

用户能够手动备份当前集合的全部已保存笔记名称、正文、标签、引用标识/关系及必要的失效识别信息，并恢复到新的独立集合。备份来源位置是给用户识别的路径，来源集合标识用于引用归属；恢复位置与新集合标识独立于备份来源。

验收方法：

1. 存在任一未保存笔记时，提示“本次备份不包含这些修改”，提供“返回保存／继续备份”。
2. 返回保存时不执行本次备份；继续时仅备份已保存版本，包括已保存标签和引用关系。
3. 所选备份目标文件已存在时拒绝覆盖，提示选择其他文件名或位置，或取消；取消及失败不修改已有文件。另选不存在的目标文件，成功时显示备份位置和笔记数量，备份可用于恢复。
4. 失败时显示原因，当前数据不变，未完成产物不得报告为有效备份。
5. 恢复目标必须为空；非空时拒绝恢复，目标已有内容和当前集合均不变。
6. 恢复成功后显示位置和数量，可打开独立集合；不覆盖、不合并当前集合。
7. 恢复后的名称、标签及有效和失效引用状态与备份时一致；正文仅允许 D3 规定的引用归属转换，其他字符和代码保持一致；有效引用在恢复集合内部跳转。
8. 用损坏备份、不可写目标等条件验证恢复失败：显示原因，当前集合和备份文件不变，未完成结果不得作为成功恢复的集合使用。
9. 备份后修改当前集合，再恢复备份，确认当前集合仍保留修改后的数据。
10. 预先放置内容已知的备份目标文件，尝试备份到相同路径，验证拒绝覆盖提示且已有文件字节保持不变，当前集合不变。另选不存在的路径时按正常备份流程验收。

外部图片和附件文件不属于首版备份保证范围，笔记中的相关路径作为文本保留。

**补充验收（D1，U14采纳；验收未执行）：**

11. 当前集合为位置 A，备份界面及备份识别信息显示来源 A、实际备份时间及已保存数量；切换至集合 B 后另作备份，来源为 B，不混入 A 的笔记。测试时产生实际时间，不预填测试记录。
12. 将 A 的备份恢复到空位置 C，显示 C 和数量；恢复完成后当前集合不自动切换。选择“打开恢复集合”或稍后通过“打开集合”选择 C，可读到恢复数据；打开时按 FR16/FR10 处理原集合未保存内容。
13. 在后续测试样例中使原位置 A 不可访问后，仍可依据有效备份恢复至空位置 C；来源 A 只用于识别，不强制原路径存在。C 中有效引用仅在 C 内解析，不跳往原集合；损坏备份或恢复失败继续满足原失败保护。
14. 用无有效集合结构的位置执行“打开集合”，显示不能打开原因，保留原活动集合；不把未完成恢复目录当作成功集合。备份文件通过“恢复”使用，不能将备份文件当作可直接编辑的活动集合。
15. 集合 X 有 A→B、C→B 的已保存有效关系，另含已删除目标的失效标记、目标不存在标记、第三集合失效标记及代码示例。备份 X，恢复到空位置 Y，检查 Y 的集合标识不同于 X；A、B、C 的对应笔记标识保留，属于 X 的非代码标记归属转换为 Y。打开 Y 后有效引用指向 Y 的对应 B，B 的反向引用包含对应 A、C，不跳回 X；其余失效状态保持，代码和普通正文原字符保持一致。
16. 把 X 中未经恢复转换的完整标记直接复制到 Y 并保存，仍显示跨集合失效，不能因 Y 恰有相同笔记标识而关联；转换仅由恢复过程按来源关系执行，不通过普通粘贴触发。
17. 同一备份再恢复到另一个空位置 Z，Y、Z 集合标识不同，各自内部有效关系正确；从 Y 复制标记到 Z 仍失效。检查 X 和备份文件内容不因恢复转换而改写。
18. 准备含重复笔记标识、关系冲突或声明有效但找不到对应目标的损坏备份，恢复拒绝并说明原因，不按名称猜配，当前集合及备份文件不变；未完成结果不报告为成功。

### FR16 笔记集合新建、打开与切换（U14 采纳的新增需求）

**来源：** [U13 第1项](#U13) 要求补充生命周期；AI [D1](#D1) 提出具体入口与失败保护，由 [U14 第1项](#U14) 明确采纳。[U03 第1项](#U03) 已确认独立恢复；引用归属与恢复转换按 [U14 第3项](#U14) 要求由本轮 AI 细化。不是题目原文明示的集合管理功能。

用户能够在空本地位置新建集合，打开已有集合及切换活动集合，并从恢复结果打开新的独立集合。集合含义及单一活动集合规则见 D1。

验收方法（实施后执行，当前未执行）：

1. 选择空目录新建，成功后显示活动集合位置，列表为空，可按 FR01 新建保存笔记；正常关闭应用后，通过“打开集合”选择该位置读回已保存数据。
2. 非空位置新建被拒绝，提示选择空位置，该位置已有文件及原活动集合不变；目标不可写时显示失败，不产生被报告为有效的集合。
3. 打开有效集合 A，列表、筛选、搜索及引用作用域为 A；成功打开 B 后显示 B 的位置与数据，不将 A 的笔记显示为 B 的数据。
4. 当前集合存在未保存笔记时，分别验证保存后切换、放弃修改后切换、取消；取消或保存失败保留原集合及编辑内容，全部处理完成且目标可打开后才切换。选择无效目标时不丢弃原集合未保存内容；只有实际切换成功才执行明确选择的放弃结果，用户已成功保存的数据不回滚。
5. 当前未打开集合时，笔记编辑、集合搜索、集合备份入口提示“请先新建或打开笔记集合”；可使用恢复入口选择备份和空位置，恢复成功后按 FR11 打开结果。
6. 将备份恢复至空位置 C，成功提示提供“打开恢复集合”，也可稍后按第1项打开 C；原集合保持独立，打开后的引用均在 C 内。
7. 断网完成以上操作；不要求集合删除、合并、跨集合引用、最近使用列表或同时打开多个集合。
8. 新建集合分配符合D3的集合标识；正常关闭/打开同一集合不改变标识。用已知标识冲突的受控样例验证拒绝继续误关联并说明原因，不修改原集合或编辑内容。没有在线全局注册或集合删除验收。

**编号及追踪影响：** FR12—FR15 保留为范围外，不复用；FR16 在 S01（开始记录）、S05（恢复后打开）、S06（离线集合操作）中映射。属于对原集合使用前提的最小补全，不增加平台或协作范围。
