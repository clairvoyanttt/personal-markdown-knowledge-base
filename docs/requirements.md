## 一、背景与问题陈述

学生与知识工作者需要持续记录、整理、查找和关联知识。随着笔记积累，用户可能面临内容难以定位、知识关系难以追踪，以及未保存修改被误丢弃等问题。这些问题根据题目和使用场景推导，未开展用户访谈验证。

本工具围绕“记录—组织—查找—关联—输出”流程，支持用户在 Windows 11 上管理个人本地 Markdown 笔记，并通过手动保存、备份和恢复保护数据。

首版目标：

- 编辑和预览 Markdown，识别未保存、已保存和保存失败状态。
- 使用标签和全文检索定位已保存笔记。
- 建立双向引用，改名后保持关联，删除后识别失效引用。
- 导出单篇 Markdown，明确内部引用和附件的限制。
- 手动备份已保存数据，恢复为独立集合，不覆盖当前集合。

## 三、统一业务规则、优先级与编号

### 3.1 数据版本与手动保存

“当前编辑版本”是当前编辑界面的内容，可能尚未保存；“已保存版本”是最近一次成功保存的数据。

| 操作或界面 | 使用的数据版本 |
|---|---|
| 当前笔记编辑界面，包括待保存名称、标签和内部引用 | 当前编辑版本 |
| Markdown 预览 | 当前编辑版本，无需先保存 |
| 笔记列表名称、标签筛选、全文搜索及引用目标名称 | 已保存版本 |
| 其他笔记的反向引用列表 | 已保存版本 |
| 单篇 Markdown 导出 | 已保存版本 |
| 手动备份 | 已保存版本 |

正文、名称、标签及内部引用的修改均需要手动保存。改名输入可在当前编辑界面显示；保存前，笔记列表、标题检索和引用目标名称仍依据已保存名称。保存时按 FR01 去除首尾空白、校验名称并排除自身判重；保存成功后更新名称，已有引用仍指向原笔记。校验或保存失败时保留待保存输入，已保存名称及引用关系不变。

统一处理规则：

1. 修改后，当前编辑界面显示修改，并标识未保存。
2. 保存前，标签筛选、全文搜索和反向引用仍依据已保存版本。
3. 保存成功后，上述结果更新。
4. 保存失败时，保留当前编辑内容，上述结果继续依据原已保存版本。
5. 普通关闭未保存笔记时，按 FR10 提醒；明确确认删除的流程按 FR01 处理。
6. 预览、检索、导出和备份不得隐式保存编辑中的修改。

预览用于检查当前编辑效果；检索和反向引用用于查找已保存知识。两者使用不同版本是明确的业务规则。

### 3.2 名称与标签

- 新建或改名时，笔记名称去掉首尾空白后保存；处理后为空则拒绝。
- 同一集合内不允许不同笔记重名。去掉首尾空白后判重，英文名称不区分大小写；改名判重排除当前笔记自身。
- 重名操作失败时，已有笔记及引用关系保持不变。
- 标签去掉首尾空白、拒绝空标签，同一笔记不重复添加同名标签。
- 英文标签区分大小写，不套用笔记名称的大小写判重规则。

### 3.3 优先级与编号

| 优先级 | 含义 |
|---|---|
| 高（H） | 核心能力、数据保护及必要异常处理。 |
| 中（M） | 辅助能力，已纳入首版，同样必须验收。 |
| 范围外 | 不纳入首版交付或验收。 |

保留 FR01—FR15、NFR01—NFR06。FR01—FR11 为首版功能需求；FR12—FR15 仅作为范围排除记录，不复用编号。

## 四、功能需求与验收标准

### FR01 笔记管理与名称唯一性

**优先级：高（H）**

用户能够新建、打开、改名和删除笔记。新建或改名时，名称去掉首尾空白后保存；处理后为空则拒绝。同一集合内不允许不同笔记重名，英文名称判重不区分大小写。改名判重时排除当前笔记自身。

验收方法：

1. 新建并保存笔记后，可从列表打开。
2. 在不存在名称冲突时，输入名称 `  Note  `，成功保存后的名称为 `Note`。
3. 输入空名称或全空白名称，拒绝新建或改名，显示原因。
4. 已有笔记 A，名称为 `Note`：
   - 新建另一篇笔记，输入 `note`、`NOTE` 或 ` Note `，均提示重名并拒绝。
   - 将另一篇笔记 B 改名为 `note`、`NOTE` 或 ` Note `，均提示重名并拒绝。
   - 对 A 自身执行上述名称操作，不得仅因与 A 的原名称匹配而提示与另一篇笔记重名。
5. 已有笔记 A，名称为 `笔记`：
   - 将另一篇笔记 B 改名为 ` 笔记 `，去掉首尾空白后判为重名，提示并拒绝。
   - 新建另一篇名称为 `笔记` 或 ` 笔记 ` 的笔记，同样提示重名并拒绝。
6. 重名失败后，不产生第二篇同名笔记；已有笔记的名称、正文、标签及引用关系不变。
7. 合法改名保存成功后，列表显示去除首尾空白后的新名称，引用行为满足 FR08。
8. 删除前显示确认提示；若存在未保存修改，同时说明“该笔记及未保存修改将被删除，首版无回收站”。取消后保留笔记、当前编辑内容及未保存状态；确认后从正常列表移除，相关引用按 FR08 处理。模拟删除失败时，已保存数据、当前编辑内容及引用关系保持不变。
9. 合法改名用例：集合已有 A（已保存名称“课程笔记”）和 C（已保存名称“复习提纲”），名称“线性代数整理”尚不存在；样例正文不含这些名称。将 A 编辑为“线性代数整理”但不保存，编辑界面可见待保存名称，列表及引用目标名称仍为“课程笔记”；标题查询“课程笔记”仍命中 A，“线性代数整理”不命中 A。保存成功后，名称和查询结果更新为“线性代数整理”，已有引用继续指向 A。
10. 重名改名用例：独立重置上述集合，尝试将 A 改为“ 复习提纲 ”。去首尾空白后与另一篇 C 重名，拒绝保存，A、C 的已保存名称及引用关系不变，待保存输入保留。
11. 保存失败用例：独立重置上述集合，输入合法且未被占用的新名称“线性代数整理”，模拟保存失败。编辑输入及未保存状态保留，列表、标题检索、引用目标名称继续使用“课程笔记”。放弃修改并关闭不提交改名。

### FR02 Markdown 源文本编辑

**优先级：高（H）**

用户能够编辑 Markdown 源文本，保存后再次打开时内容保持一致。

验收方法：输入包含中文、英文、标点、多行文本和围栏代码块的样例，手动保存并重新打开，正文字符及换行与保存时一致。

### FR03 Markdown 预览

**优先级：中（M）**

用户能够预览当前编辑版本中的标题、段落、列表、链接、引用和围栏代码块。

验收方法：

1. 使用包含上述六类内容的固定样例，分别检查对应结构。
2. 修改正文但不保存，预览显示修改后的内容；搜索仍依据已保存版本。
3. 围栏代码块保留其中字符和换行，不把代码内容解释为普通 Markdown。
4. 预览不修改源文本。

公式、表格和原始 HTML 等扩展语法不纳入首版验收承诺；链接呈现测试不要求访问外部网站。

### FR04 标签编辑与筛选

**优先级：高（H）**

用户能够添加、移除标签，并按已保存标签筛选笔记。标签修改需要手动保存。

验收方法：

1. 输入 `  AI  `，当前编辑界面显示标签 `AI`。
2. 空标签及全空白标签被拒绝。
3. 同一笔记重复添加 `AI` 不产生重复项；`AI` 和 `ai` 可以作为不同标签存在。
4. 在 A 中添加标签但不保存，编辑界面可见该标签，筛选时 A 不因本次修改进入结果；保存成功后进入结果。
5. 从 A 移除该标签但不保存，编辑界面显示移除结果，筛选仍包含 A；保存成功后才移除 A。
6. 标签保存失败时，保留编辑中的修改，筛选仍依据原已保存版本。
7. 仅修改标签后关闭，也触发 FR10 的未保存提醒。

### FR05 全文检索

**优先级：高（H）**

用户能够对已保存笔记的标题和正文进行连续字面匹配检索，英文不区分大小写。

验收方法：

1. 标题及正文中的唯一关键词均能检索到对应笔记；点击结果打开对应笔记。
2. `Markdown` 可被 `markdown` 命中。
3. 正文包含“知识管理”时可命中该查询；仅包含“知识与管理”时不能据此命中。
4. 查询为空，或仅包含空白字符（如空格、制表符）时，提示输入关键词，不执行检索，并清除旧查询结果。分别用空字符串、三个空格和一个制表符验证。其他查询仍按既定连续字面匹配规则处理，不额外裁剪非全空白查询。
5. 无匹配时明确显示无结果，不残留上次结果。
6. 新增关键词但未保存时不能据此命中，保存后可以命中。
7. 删除已有关键词但未保存时，仍能按原已保存内容命中；保存后不再据此命中。
8. 保存失败时，结果继续依据原已保存版本。

标签不属于全文检索字段，按 FR04 单独筛选。

### FR06 内部引用编辑与跳转

**优先级：高（H）**

用户能够建立或移除指向同一集合内其他笔记的内部引用。引用编辑需要手动保存。

验收方法：

1. 在 A 中添加指向 B 的引用，当前编辑界面立即可见；保存后激活引用可打开 B。
2. 添加引用但未保存时，B 的反向引用不因本次修改出现 A；保存后出现 A。
3. 移除引用但未保存时，编辑界面显示移除结果，B 的反向引用仍包含 A；保存后才移除 A。
4. 按 FR01 验证名称规则，目标列表不存在同一集合内的重名候选项。
5. 新建另一篇笔记或将另一篇笔记改为与 B 冲突的名称，操作失败后，A 中已有引用仍指向原 B。冲突按 FR01 的去首尾空白及英文不区分大小写规则判断。
6. 仅增删内部引用后关闭，也触发 FR10 的未保存提醒。

不规定内部引用必须采用哪种技术实现。

### FR07 反向引用

**优先级：高（H）**

用户能够查看哪些已保存笔记引用当前笔记，并打开引用来源。

验收方法：

1. A、C 引用 B 并保存后，B 的反向引用包含 A、C。
2. 从列表可以打开对应来源笔记。
3. A 移除引用但未保存时，列表仍包含 A；保存成功后移除 A，保留 C。
4. 新增引用未保存时不更新列表；保存失败时也不更新。
5. 重新打开集合后，反向引用与已保存关系一致。

### FR08 引用目标改名与删除

**优先级：高（H）**

合法改名后已有引用继续指向原笔记；目标被删除后，引用显示失效。

验收方法：

1. A 引用 B，选择集合中尚不存在的新名称 B2，将 B 合法改名并保存后，A 的引用仍打开原笔记，B2 的反向引用仍包含 A。保存前引用目标名称仍依据已保存名称 B。
2. 将 B 改为与同一集合内另一篇笔记冲突的名称，或改为去除首尾空白后为空的名称，操作被拒绝，原引用关系不变。冲突按 FR01 判断，并排除 B 自身；合法的自身名称调整按第 1 项验证引用保持关联。
3. 删除 B2 后，A 中相关引用显示失效，激活时提示目标已删除或不可用。
4. 随后新建名为 B2 的另一篇笔记，原失效引用不能自动关联到新笔记。

不限定实现引用身份和关联保持的内部技术。

### FR09 单篇 Markdown 导出

**优先级：高（H）**

用户能够导出单篇笔记的已保存版本。内部引用转换为不可点击的可读普通文本，外部网页链接保留原样，图片和附件不打包。

有效内部引用输出示例：

    内部引用：数据结构复习（仅供识别，导出后不支持应用内跳转）

失效内部引用输出示例：

    失效内部引用：数据结构复习（目标已删除，无法跳转）

验收方法：

1. 导出前提示：内部引用不保留应用内跳转能力，图片和附件不打包。
2. 当前笔记存在未保存修改时，提示导出不包含这些修改，提供“返回保存／继续导出”。
3. 返回保存时不执行本次导出；继续时仅导出已保存正文和引用状态，不包含编辑中的正文或引用修改。
4. 内部引用输出不生成 Markdown 链接、Wiki 链接、应用链接或 HTML 链接，在 Markdown 阅读器中不表现为有效内部链接。
5. 目标名称包含 Markdown 特殊字符时，也不能使转换结果形成链接。
6. 外部网页链接的 Markdown 源文本保持原样；图片和附件路径保留原文本，不复制资源文件。
7. 成功后显示文件位置；失败时显示原因，不提示成功，源笔记不变。所选导出目标文件已存在时，拒绝覆盖，提示选择其他文件名或位置，或取消；取消及失败均不修改已有文件。
8. 预先放置内容已知的目标文件，尝试导出到相同路径，验证拒绝覆盖提示且已有文件字节保持不变；取消后源笔记不变。另选不存在的路径时，按正常导出流程验收。
9. 文件可用文本编辑器读取，除规定的引用转换外，正文、中文及代码保持一致。

### FR10 手动保存与关闭保护

**优先级：高（H）**

用户手动保存笔记，识别未保存、已保存和保存失败状态。正文、名称、标签和内部引用修改受同一保存规则约束。普通关闭和退出采用关闭保护；经明确确认的删除操作按 FR01 的删除流程处理，不重复执行普通关闭提示。

验收方法：

1. 分别只修改正文、只编辑名称、只修改标签、只增删引用，均出现未保存状态。
2. 保存成功后显示已保存状态，重新打开可读取保存后的正文、名称、标签和引用。
3. 保存成功后，笔记列表名称、标签筛选、全文检索、引用目标名称及反向引用更新为新版本，引用目标身份保持不变。
4. 模拟保存失败：显示原因，保留当前编辑内容及未保存状态；列表名称、筛选、搜索、引用目标名称和反向引用继续使用原已保存版本。名称校验失败时同样不更新已保存数据。
5. 普通关闭未保存笔记时提供“保存后关闭／放弃修改并关闭／取消”，名称修改也适用：
   - 保存后关闭：仅在保存成功后关闭。
   - 放弃修改并关闭：不提交编辑中的修改，已保存版本保持不变。
   - 取消：留在编辑界面并保留修改。
6. 退出应用时，对所有未保存笔记执行同等保护。
7. 修改后不主动保存，不能因预览、筛选、搜索、导出或备份而被自动保存。
8. 删除含未保存修改的笔记时，按 FR01 显示说明未保存修改会被删除的确认。取消后编辑内容和未保存状态保留；确认后删除并按 FR08 更新失效引用；删除失败时不改变已保存数据及引用关系。

### FR11 手动备份与独立恢复

**优先级：高（H）**

用户能够手动备份当前集合的全部已保存笔记名称、正文、标签和内部引用关系，并恢复到新的独立集合。

验收方法：

1. 存在任一未保存笔记时，提示“本次备份不包含这些修改”，提供“返回保存／继续备份”。
2. 返回保存时不执行本次备份；继续时仅备份已保存版本，包括已保存标签和引用关系。
3. 所选备份目标文件已存在时拒绝覆盖，提示选择其他文件名或位置，或取消；取消及失败不修改已有文件。另选不存在的目标文件，成功时显示备份位置和笔记数量，备份可用于恢复。
4. 失败时显示原因，当前数据不变，未完成产物不得报告为有效备份。
5. 恢复目标必须为空；非空时拒绝恢复，目标已有内容和当前集合均不变。
6. 恢复成功后显示位置和数量，可打开独立集合；不覆盖、不合并当前集合。
7. 恢复后的名称、正文、标签及有效和失效引用状态与备份时一致；有效引用在恢复集合内部跳转。
8. 用损坏备份、不可写目标等条件验证恢复失败：显示原因，当前集合和备份文件不变，未完成结果不得作为成功恢复的集合使用。
9. 备份后修改当前集合，再恢复备份，确认当前集合仍保留修改后的数据。
10. 预先放置内容已知的备份目标文件，尝试备份到相同路径，验证拒绝覆盖提示且已有文件字节保持不变，当前集合不变。另选不存在的路径时按正常备份流程验收。

外部图片和附件文件不属于首版备份保证范围，笔记中的相关路径作为文本保留。
