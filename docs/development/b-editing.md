## 已实现

- `application/editing/service.py`：API02 Create/Load/Apply/Save及API11 Check/CloseUnconfirmed。内存状态带锁，UI同步编辑和后台不可变快照共用一个源；纯服务不依赖Qt/SQL。
- 所有接受的编辑推进`edit_version`。允许名称/正文暂时非法并保留输入，标签须先校验接受；标签原始输入框另行保留。按设计的明确空白集合裁剪，不用默认strip/casefold扩大规则。
- Load同篇已打开笔记复用现有buffer，不覆盖未保存输入；首次加载保存版为干净状态。新草稿没有note_id/base_revision且为未保存状态。
- 保存前冻结完整当前快照并校验命令；每命令只发出一次。成功只确认捕获版本k、推进身份/base_revision，后来输入仍保留且未保存。明确NOT_COMMITTED保留输入和旧事实；普通异常、失配证据和底层取消均不能冒充回滚，而进入PENDING。
- 待核实时可继续内存编辑/新建；阻止新的写入、新读取保存版及集合切换，已打开buffer仍可查看。API11的OK+NOT_COMMITTED只表示核实完成，不表示保存成功。
- 取消外层await后继续等待实际底层结果；迟到取消不覆盖已确认提交。证据匹配集合/代次、原SAVE命令、拟用note_id、捕获快照及严格整数版本；不能拿恢复/删除回执或缺回执证明SAVE结果。
- 未知退出要求两项风险确认、全部最新buffer版本、已结束原底层调用；复制并冻结版本映射。许可不立即丢弃草稿，最终Qt边界再次检查；新编辑/新buffer/结果转已知均使旧许可失效。
- `desktop/editor_session.py`：真实B CollectionSession，通过QtDispatcher在同一回调/状态锁中核对全部版本、上下文、取消、无待核实；只有真实激活后才丢弃明确选择放弃的草稿并安装新位置。
- `desktop/editor.py`：集合新建/打开/切换、会话草稿选择、名称/正文编辑、增删标签、Ctrl+S、核实入口及保存/放弃/取消关闭。调用A真实集合服务，不在界面直接SQL。退出先收束在途工作、检查业务许可，再关闭运行器并等资源收尾。
- `text_edit.py`：编辑显示与原始正文之间保留未变化源片段；改名、增删标签、局部输入不会无意改写原CRLF、CR、NBSP及Unicode分隔符。
- `preview.py`：版本化预览消费端及可注入统一渲染适配；Qt只接受当前集合/当前buffer/当前edit_version结果，阻止远程及本地嵌入资源自动读取。**没有另写Markdown/引用解析器，也没有宣称六类预览完成。**

## 操作和真实限制

在标准CPython3.12环境按README安装后运行：

```powershell
.\.venv\Scripts\python.exe -m pmkb
```

默认启动B编辑开发窗口；不会自动建立用户配置或集合。先选空位置新建集合或打开有效集合，再新建草稿。名称、正文、标签都须手动保存；没有自动保存或退出后的内存草稿恢复。保存版列表与会话草稿明确分开，不能把未保存名称当搜索或反向引用事实。

当前main缺少C真实存储/统一解析/查询服务，因此默认`storage=None`和`preview_renderer=None`。保存会明确返回STATE_BLOCKED，草稿仍在内存；预览和保存版查询区显示待接入，不显示假数据或假成功。无法加载实际保存笔记列表、确认删除、引用插入/跳转/反向引用、导出/备份/恢复；这些入口需要对应正式契约和服务后继续接线。**当前不是可独立持久化使用的完整笔记产品。**

`create_main_window(config_file, storage, preview_renderer)`允许集成适配。配置必须为绝对路径；A负责真实登记。`create_startup_window()`保留A无编辑器启动壳，仅用于原运行器生命周期检查；真实草稿不能接HeadlessCollectionSession或套用壳的无业务关闭。

## 向C/A/D交接

`application/editing/ports.py`是B提出的内部窄端口，**不是已经批准的API10/公共契约**，待C/B共同核对后适配或替换；现有`contracts`类型没有改动。

| 输入/返回 | 约束与责任 |
|---|---|
| `SavedNote` | C返回本集合保存版的身份、revision、名称/正文/标签；不存在返回None；读异常不丢草稿 |
| `SaveAttempt` | B生成context、command_id、pending_save_id、拟用note_id及原冻结DraftSnapshot；name/tags规范化仍按设计，正文必须保持原文 |
| `SaveEvidence.COMMITTED` | C在专属连接线程执行原子事务，正向核对同集合、本SAVE、原笔记与版本/内容/lastCommitId；返回保存版本=base+1及真实集合版本 |
| `NOT_COMMITTED` | 必须有确定未提交/已回滚证据，可以附业务AppError；仅回执缺失不够 |
| `UNRESOLVED` | 证据不足，两个成功版本均为空；B保留PendingSave且不重发 |
| `PreviewRenderer` | B渲染消费适配必须使用C的统一AST/引用分类；不另造解析器、不执行脚本/加载资源、不隐式保存。具体共享ParsedDocument仍待C接口 |

C须在事务内再次验证名称/标签及判重、base_revision、解析/跨度、引用派生、回执及集合版本；B的输入检查不能代替数据库服务。B暂有私有输入接受函数以保护本批标签交互，待C共享校验落地后复用，不能长期保留两套漂移规则。

A集合协调器已通过真实B会话联调。D的输出/备份/恢复尚未跨分支集成；不能基于未合并PR编造联调结果。后续必须保持新草稿无保存版不导出、保存版输出/备份及未保存提示。API03/04/05/07/09/10最终类型需要相应提供方/调用方核对。本批未擅自实现C事务或D文件发布，也未代替成员发认领/权限消息。

### 已复现并修复（全部在上次提交文件内）

1. 退出等待期间缺少取消入口：新增状态栏“取消退出”，保持Qt事件循环响应；取消后恢复编辑，不推断原任务回滚。取消还会撤下退出轮询，迟到的保存结果/退出许可不能重新触发关闭。
2. 核实原SAVE过程中取消且仍无可靠证据：按API11返回CANCELLED、Value为空，保留PendingSave及原保存事实。可靠判定已形成时仍按真实结果返回。未知退出缺少确认或版本过期统一STATE_BLOCKED。
3. API11返回OK+NOT_COMMITTED时原来只显示“操作完成”：现明确显示原保存未提交、草稿保留；COMMITTED只说明捕获版本，不能把后来输入标保存。
4. Load原来会把保存版的非规范标签裁剪后标干净，也未拒绝无效Unicode正文：现拒绝不规范名称/标签及无配对代理项，不默默改写保存事实。
5. 关闭确认原来可能把笔记名当富文本解释：改为显式PlainText，不把合法名称中的HTML样式文字作为格式或资源。
6. 无效相对配置路径原来在启动后台线程之后才被拒绝：现在线程启动前验证，避免构造失败留下后台运行器。
7. 后台CancelledError原来未由UI完成回调消费；普通预览异常还可能清除无关切换/退出状态：现完整消费异常结果，按操作分别收束。过期预览失败与成功一样按buffer/edit_version丢弃，不能覆盖新状态。
